# Features

Numbered register of every end-user visible feature; a number is never reused. Every feature is covered by tests listed in [TESTS.md](TESTS.md); the guard `tests/docs-contract.sh` fails when a feature has no test.

- **F1 — No secret in the image.** The image carries no database password and no key or salt. Without a database password the connection fails at once; keys and salts the operator does not set are generated at random on the first start and kept in `/app/wp-secrets`. Found in the existing image.
- **F2 — Headless image.** The image has no shell, no busybox and no perl; only php-fpm and the PHP CLI run. Found in the existing image.
- **F3 — Debug mode from the environment.** The operator switches WordPress debugging at container start, without a configuration file: off by default and with `false`, empty, `0`, `off` or `no`; debug on with errors in the container log with `true`, `on`, `yes`, `1` or `display`; debug on with errors in `wp-content/debug.log` with `log` or `all`. A log file path switches debug on and writes there. Errors are never shown in the browser, also with `display` and `all`. An unknown value leaves debug off and writes a line naming the value into the container log.
- **F4 — Internal host from the environment.** The host and port under which WordPress reaches its own nginx inside the container network is set at container start, default `wordpress-nginx:8080`. WordPress' own calls to itself (WP-Cron, REST requests to `localhost` or to the configured home URL) go to that host, and REST URLs handed to the browser carry the external home URL and never that internal host, also when the operator changes it.
- **F5 — Plugin and theme installation switch.** The operator decides at container start whether the WordPress administrator may install, update and delete plugins, themes and language packs: allowed by default, forbidden with `true`. A value that is neither true nor false keeps the default and writes a line naming the value into the container log.
- **F6 — WordPress memory limit.** The operator sets the memory WordPress asks for at container start, as a size such as `256M`; unset, WordPress keeps its own limit. A value that is no size is ignored and named in the container log.
- **F7 — PHP limits from the base image.** The memory limit, upload size, POST size, number of uploaded files, execution time, input time and number of PHP processes are set at container start with the variables of mwaeckerlin/php-fpm and its defaults `512M`, `10G`, `100G`, `1000`, `30`, `60` and `50`.
